# 阶段七硬件契约与实施计划：5V白光补光LED

> 建立日期：2026-08-24（Asia/Shanghai）  
> 当前状态：**实物已接线；DTS/Kernel已实现、编译并部署，等待新Image真机验收**  
> 边界：P1.6相机BSP核心已关闭；P1.7是独立补光外设，不阻塞项目二启动

## 1. 实物接口

用户提供的模块资料只明确：

| 模组引脚 | 资料定义 |
|---|---|
| G | GND，与控制板共地 |
| V | 5V DC输入 |
| S | GPIO/PWM控制输入 |

照片可见模组自带Q1、R1、R2，说明S不是LED功率电流通路；但资料未给出模块
最大/持续电流、功率、输入高低阈值、控制极性和允许温升。因此软件按常见的
3.3V active-high控制实现，首次上板必须验证“亮度0=灭”，再从1/255逐步增加。

## 2. 底板V1.2接线契约

底板原理图第3页POWER IO证明：

| LED | 底板接点 | 网络 |
|---|---|---|
| V | JP2 pin 2、4、6任一 | VCC5V0_SYS |
| G | JP2 pin 1、3、5任一 | GND |
| S | JP5 pin 10 | GPIO0_C6 / PWM5_M1，3.3V I/O域 |

用户已经按该契约接线。板端验收前保持开发板断电；禁止带电拔插。

## 3. Pinmux与资源冲突

JP5 pin 10不是电源脚。它在基准DTS中同时被两个可选节点引用：

- `rm500u_5g_modem`：GPIO0_C6作为5G复位；
- I2C5 `pcf8563@51`：GPIO0_C6作为中断。

目标板实际使用I2C6的AT8563/PCF8563兼容RTC；I2C5的同地址节点未绑定。因此
P1.7 DTSI禁用可选5G节点和未使用的I2C5 RTC节点，保留I2C6 RTC，再启用：

```text
GPIO0_C6 -> PWM5_M1
PWM period = 50000 ns = 20 kHz
brightness = 0..255
default = off
```

若以后需要5G模块，必须先关闭/断开LED并恢复原DTS，二者不能共用该引脚。

## 4. 软件实现

| 项目 | 实现 |
|---|---|
| DTSI | `rk3588-alientek-led-stage7.dtsi` |
| 内核配置 | `CONFIG_LEDS_PWM=y` |
| Linux接口 | `/sys/class/leds/zzh:white:fill/brightness` |
| 验收脚本 | `scripts/verify_led_stage7.sh` |
| 默认状态 | LED class注册后brightness=0、PWM正常极性0%占空比 |

当前5.10 `leds-pwm`驱动初始化brightness为`LED_OFF`并立即应用0%占空比。
DTS同时保留`default-state = "off"`表达硬件契约。

## 5. 首次上板门禁

1. 只允许执行`run nfsbootfdt`加载P1.7新Image/DTB，不进入原厂系统；
2. 启动过程中LED必须保持熄灭；若全亮，立即断电；
3. 检查LED class、brightness=0、PWM5 pinmux和冲突节点disabled；
4. 写brightness=1，用户确认微亮；再按4、8、16、32逐级验证；
5. 每级仅短时观察，检查模组和线材是否异常发热；
6. 写0并确认熄灭；
7. 双路300 NV12+80 Meta回归，确认补光节点不影响相机链路。

没有电流/功率数据前，不执行255长时间满亮，不声称完成电流、功耗和温升验收。
