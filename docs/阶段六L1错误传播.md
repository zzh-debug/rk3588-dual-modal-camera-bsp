# 阶段六 L1 超时与用户态错误传播

> 实现日期：2026-08-24（Asia/Shanghai）  
> 当前状态：**P1.6-C受控超时、mainpath EIO、关闭/重开及代际隔离真机门禁通过**

## 1. 实现边界

项目二实际从 `rkisp_mainpath` 获取NV12，RKISP online路径不会在RKCIF capture
node完成VB2 Buffer。因此L1错误必须发送到当前应用真正等待的RKISP mainpath
VB2队列；只给未使用的RKCIF RAW队列调用 `vb2_queue_error()` 无法唤醒项目二。

本次只实现L1：

- 检测成功VB2 done心跳超时；
- 设置当前mainpath队列error并唤醒poll/DQBUF；
- 用户态收到EIO后关闭并重新打开；
- 不在内核里跨Sensor/CSI/RKCIF/RKISP透明重启。

## 2. 生命周期

每个 `rkisp_stream` 增加独立状态：

| 字段 | 用途 |
|---|---|
| `l1_generation` | 每次mainpath STREAMON递增 |
| `l1_timer_generation` | delayed work创建时绑定的代际 |
| `l1_last_heartbeat_ns` | 最近一次成功VB2 done |
| `l1_timeout_count` | 该stream累计超时次数 |
| `l1_armed/l1_triggered` | 当前会话状态 |
| `l1_timeout_work` | generation-aware delayed work |

STREAMOFF、close和video node注销均先解除armed状态，再同步取消delayed work。
work只有在streaming、enabled、armed且generation匹配时才能调用
`vb2_queue_error()`，旧会话任务不能处理新会话。

## 3. 默认关闭与测试接口

参数位于 `/sys/module/video_rkisp/parameters/`：

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `l1_timeout_enable` | 0 | 启用mainpath L1超时 |
| `l1_timeout_ms` | 1000 | 超时，内核限制100–10000ms |
| `l1_fault_drop_heartbeat` | 0 | 仅测试：抑制心跳以稳定触发超时 |

所有新增功能默认关闭。故障开关不停止硬件、不修改I2C或DMA地址，只让L1观察器
看不到心跳，用于验证用户态EIO和关闭/重开闭环。

## 4. 自动验收

```sh
verify_rkisp_l1_timeout_stage6 /tmp/rkisp-l1-timeout-stage6 500 300 80
```

门禁要求：

1. 注入时采集不能正常完成，也不能等到外层10秒timeout；
2. 用户日志必须出现Input/output error；
3. dmesg必须且只能出现一次带generation的L1 timeout；
4. 清除注入后关闭/重开，300 NV12 + 80 Meta双路采集PASS；
5. 新会话不得出现残留timeout。

L1实现达到“检测、向实际用户队列传播EIO、用户态关闭重开”的目标。它不做Host无感透明恢复；测试开关和timeout均恢复为安全默认值。
