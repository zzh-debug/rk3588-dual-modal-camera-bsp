# 阶段五总结：MLX90640 V4L2 Meta/VB2 ABI

> 验收日期：2026-08-24（Asia/Shanghai，采用开发宿主机时间）  
> 平台：ATK-DLRK3588，Rockchip Linux 5.10.209 #5  
> 结论：**P1.5 built-in板端验收通过**

## 1. 验收范围

本阶段把P1.4已验证的400 kHz原始传输封装为稳定的应用层接口：独立
`zzh,mlx90640` I2C驱动、EEPROM NVMEM缓存、版本化 `ZMLX` Meta ABI、VB2
MMAP/poll、pair sequence、双Subpage单调时间戳、STREAMOFF Buffer回收和
control恢复。

温度计算、坏点、滤波、伪彩和跨光谱映射属于项目二；双路并采和RKCIF错误
恢复属于P1.6。

命令：

## 5. 外置模块补充可靠性

同一权威源码在重启前还通过：

- 200对/10周期；
- 100次STREAMON/OFF；
- 进程在第14对异常终止后自动STREAMOFF并立即重开；
- 500ms慢消费，`pairs=16 no-buffer=32 duplicate=0`；
- 慢消费结束后立即恢复正常10对；
- NVMEM 1664-byte黄金哈希。

证据位于 `evidence/stage5/2026-08-24/`。

## 6. 共享总线和当前阻塞

- I2C5 Goodix `5-0014`正常读取ID 911并绑定；
- FUSB302 `5-0022`保持驱动绑定；
- MLX正式测试没有新增I2C、queue、timeout、duplicate或内核崩溃日志。

IMX415在本次重启后仍读取 `0x311a` NACK `-6`，`3-001a`未绑定，RKCIF没有
terminal sensor。因此P1.6双路并采暂时阻塞。这不影响MLX P1.5验收结论，
因为故障在MLX开始采集前已经出现，且两者位于不同I2C控制器。

## 7. 结论

P1.5已关闭。项目一现在能够向用户态提供经过真实硬件验证的：

```text
MLX90640 EEPROM NVMEM
MLX90640 ZMLX Meta Buffer
连续双Subpage pair
CLOCK_MONOTONIC双时间戳
MMAP/poll/sequence
STREAMOFF/异常关闭恢复
```

下一阶段为P1.6：恢复IMX415健康主路径后运行双路并采脚本，再依据健康基线加入
RKCIF逐stream统计、tracepoint和generation-aware L1错误传播。
