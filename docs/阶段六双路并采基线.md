# 阶段六双路并采基线：IMX415 NV12 + MLX90640 ZMLX Meta

> 验收日期：2026-08-24（Asia/Shanghai，采用开发宿主机时间）  
> 当前状态：**P1.6-A双路并采基线通过；RKCIF可观测性和L1错误传播待实现**  
> 平台：ATK-DLRK3588，Linux 5.10.209 #5，NFS RootFS

## 1. 前置状态

用户重新插拔IMX415排线，先在原厂系统确认摄像头可用，再执行
`run nfsbootfdt`。新NFS会话自动probe：

```text
3-001a -> zzh_imx415
reference register 0x311a = 0xe0
dphy0 matches zzh_imx415 3-001a
rkcif-mipi-lvds2 notifier completed
RKISP input: 3840x2160 SGBRG10 @ 30fps

5-0033 -> zzh_mlx90640
ZMLX Meta v1: 3400 bytes
16 Hz Subpages / 8 Hz complete pairs
```

这证明此前IMX NACK来自物理接触或上电状态，而不是MLX驱动或双路并采造成。

## 2. 自动化脚本

权威脚本：`scripts/verify_dual_capture_stage6.sh`。

脚本动态发现 `rkisp_mainpath`，并行启动：

```text
v4l2-ctl: RKISP 3840x2160 NV12, MMAP/poll
verify_mlx90640_stage5: ZMLX Meta, MMAP/poll
```

分别检查NV12 DQBUF/sequence/bytesused、Meta pair数量和ABI、RKISP ErrCnt、
MLX no-buffer/duplicate及测试期间新增fatal dmesg。

脚本SHA-256：

```text
208374d59a8addd3b37296810b3af99db73d3977cc8e629e283eae6805969002
```

## 5. 结论与边界

P1.6-A双路并采基线通过，证明在同一真实硬件会话中：

- IMX415可稳定输出4K NV12；
- MLX90640可稳定输出成对ZMLX Meta；
- 两路并行不会造成sequence断号、bad bytesused、RKISP错误或MLX缺Buffer；
- 项目二所需的真实可见光帧、热pair和单调时间戳接口已经具备。

这不是P1.6全部完成。后续仍需：

1. 更长时间并采和CPU/内存/温度统计；
2. RKCIF逐stream FS/FE/DMA/VB2 debugfs统计；
3. tracepoint；
4. generation-aware帧超时；
5. `vb2_queue_error()`及用户态关闭/重开；
6. 受控故障注入和Buffer守恒。

项目二可以开始P2.1真实双路采集与时间匹配，项目一P1.6可靠性工作并行继续。
