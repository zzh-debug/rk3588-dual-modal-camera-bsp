## 5. 2小时门禁中途问题与修正

第一次后台尝试因热端验收工具单次pair上限为10000，57600目标被参数校验拒绝，
实际只有可见光运行，不能计入双路长稳。工具上限已扩展为1000000；采集、ABI、
校验和Buffer逻辑未改变。

第二次真正双路运行中，约165秒、1292个热pair时出现一次`-EILSEQ`：

```text
invalid frame data -> capture failed, propagating queue error: -84
stream stopped: pairs=1292 no-buffer=0 duplicate=0
```

可见光当时仍连续运行；中检时已到56173帧。资源32组样本为
MemAvailable 7,484,700–7,541,580kB、thermal 33.307–36.076°C，L1新增误报0，
因此不是内存、温度或可见光链路失稳。

### 5.1 根因

驱动按Melexis参考API检查Pixel/Aux中的`0x7FFF`并返回frame data error，但当前
线程把第一次`-EILSEQ`直接升级为永久VB2 queue error。参考API负责标记坏帧，
是否重试由调用者决定。长稳证明“单次坏Subpage即永久停流”策略过于激进。

参考实现：
`https://github.com/melexis/mlx90640-library/blob/master/functions/MLX90640_API.c`。

### 5.2 修正策略

- 单次`-EILSEQ`只丢弃当前Subpage和未完成pair；
- 记录`invalid_subpage`并重新从下一有效Subpage配对；
- 成功Subpage清零连续错误计数；
- 连续超过8次frame error才升级为queue error；
- I2C错误、control变化、ready timeout仍立即传播，不被掩盖；
- STREAMOFF日志增加`invalid=`计数。
