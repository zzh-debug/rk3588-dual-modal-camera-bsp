# 阶段三总结：IMX415 RKCIF RAW 与 RKISP NV12

> 验收日期：2026-08-21（Asia/Shanghai）  
> 平台：ATK-DLRK3588，Rockchip Linux 5.10.209，实物屏 1080x1920 版本  
> 结论：**P1.3 目标路径板端验收通过**

## 1. 验收范围

本阶段在 P1.2 独立 `zzh,imx415` 固定模式驱动基础上，验收 Sensor 经 RKCIF
输出 3840x2160 GB10，以及同一输入经 RKISP mainpath 输出 3840x2160 NV12 的
实际采集链路。验收覆盖格式、Buffer 大小、sequence、时间戳、300/3000 帧
连续采集、Controls 可观测效果、停流资源状态和目标路径内核错误。

本轮没有修改内核驱动、DTS、U-Boot 或 RootFS，也没有重启开发板；直接复用
已经通过 `run nfsbootfdt` 启动的 NFS 系统完成验收。

## 2. 启动与载荷门禁

板端实测为 Linux 5.10.209，`/proc/cmdline` 包含 `root=/dev/nfs`，根挂载为：

```text
192.168.5.11:/home/zzh/workspace/myproject/nfs_rootfs/atk_dlrk3588 on / type nfs
eth0: 192.168.5.20/24
```

运行 DT 中 `zzh,imx415` 为 `okay`、同地址原厂 `sony,imx415` 为 `disabled`，
`3-001a` 绑定 `zzh_imx415`。因此本轮不是 eMMC 旧系统或旧 DTB 上的误测。

## 3. Media Graph 与格式

RKCIF 路径：

```text
zzh_imx415 3-001a (/dev/v4l-subdev2)
  -> rockchip-csi2-dphy0
  -> rockchip-mipi-csi2
  -> rkcif-mipi-lvds2
  -> stream_cif_mipi_id0 (/dev/video22)
```

RKISP 路径：

```text
rkcif-mipi-lvds2 (/dev/v4l-subdev4)
  -> rkisp-isp-subdev
  -> rkisp_mainpath (/dev/video44)
```

格式契约：

| 层级 | 格式/尺寸 | Buffer |
|---|---|---:|
| Sensor | 3864x2192 SGBRG10，4 lanes，891 Mbps/lane | 不适用 |
| RKCIF crop/output | (12,16) 3840x2160 GB10，bytesperline=4864 | 10,506,240 bytes |
| RKISP input | 3840x2160 SGBRG10_1X10 | 不适用 |
| RKISP mainpath | 3840x2160 NV12，bytesperline=3840 | 12,441,600 bytes |

## 4. RAW 与 NV12 连续采集

所有测试都先丢弃 8 个稳定帧；DQBUF 日志因此包含 `8 + 正式帧数` 条记录。

| 路径 | 正式帧数 | DQBUF/sequence | bytesused | 时长/帧率 | 结果 |
|---|---:|---|---|---|---|
| RKCIF GB10 | 300 | 308，`0..307`，0 gap | 全部 10,506,240 | 约 30 fps | PASS |
| RKCIF GB10 | 3000 | 3008，`0..3007`，0 gap | 全部 10,506,240 | 约 100.50 s | PASS |
| RKISP NV12 | 300 | 308，`0..307`，0 gap | 全部 12,441,600 | 30.00 fps | PASS |
| RKISP NV12 | 3000 | 3008，`0..3007`，0 gap | 全部 12,441,600 | 100.54 s | PASS |

单帧 RAW 与 NV12 的大小、哈希和基础数据统计见
`evidence/stage3/2026-08-21/README.md`。数据统计证明输出不是空 Buffer 或单一
常量，但当前没有 ISP IQ 标定和标准色卡，故不把它表述为最终色彩/画质验收。

## 5. Controls 动态效果

在同一场景中分别设置曝光和模拟增益并抓取 NV12，Y 平面均值为：

```text
exposure=200,  gain=0   -> 14.235
exposure=2000, gain=0   -> 28.520
exposure=200,  gain=120 -> 110.091
```

这证明曝光和模拟增益不是只有控件读写返回成功，而是会改变实际输出亮度。

把 VBLANK 从 58 增到 2308，即把 VTS 从 2250 行增到 4500 行后，实测平均
帧周期从 33.333 ms 增到 66.667 ms；恢复后重新采流为 30 fps。最终 Controls
已恢复为：

```text
exposure=2242
vertical_blanking=58
analogue_gain=0
```

## 6. 停流和错误状态

- RKCIF 停流日志均结束于 `dma_en 0x0`。
- 每次测试后 `3-001a/power/runtime_status` 回到 `suspended`。
- RKISP 长测后 `ErrCnt=0`。
- 目标链路没有 overflow、timeout、IOMMU fault、DMA error、Oops、BUG 或 panic。
- 其他未接摄像头实例的 `remote terminal sensor failed` 不属于本轮目标 graph。
- 已观察到的 `mmcblk0p8` EXT4 bitmap checksum 问题与相机链路无关；当前根为
  NFS，本轮没有对 eMMC 分区执行修复操作。

## 7. 结论与下一阶段

P1.3 的独立 Sensor-RKCIF-RKISP 主路径已完成正式 RAW/NV12 和 Controls 动态
验收，可以关闭。新增 `scripts/verify_imx415_stage3.sh` 把本轮门禁固化为可重复
执行的板端检查；该脚本随后以 3/5 帧缩短参数在板端完整实跑，退出码 0 且
输出 `STAGE3_RUNTIME_CHECK=PASS`。详细日志归档于
`evidence/stage3/2026-08-21/`。

下一阶段切换到 P1.4：先确认 MLX90640 实物、电压、I2C 总线/地址和可接受总线
频率，再进行原始 RAM/EEPROM 分段读取与 EEPROM 缓存。V4L2 Meta/VB2 ABI
属于 P1.5；RKCIF debugfs/tracepoint、generation-aware timeout 和
`vb2_queue_error()` 必须以实际故障和 Buffer 守恒证据驱动，保留到 P1.6，
不在当前无故障的 IMX415 主路径上提前堆补丁。
