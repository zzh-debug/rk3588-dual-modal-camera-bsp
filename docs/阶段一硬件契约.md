### 7 位地址、线上的地址和 DTS 写法

三种写法必须分开：

```text
DTS / Linux i2c_client->addr: 0x1a       # 7-bit address
I2C write address byte:        0x34       # (0x1a << 1) | 0
I2C read address byte:         0x35       # (0x1a << 1) | 1
```

实验 DTS 只写 `reg = <0x1a>`；驱动的 `i2c_msg.addr` 也填写 `client->addr`，I2C 核心负责线上的 R/W 位。

### 上电时序

Sony 手册（打印页 84-86）规定：

1. 电源上升顺序为 `DVDD 1.1 V -> OVDD 1.8 V -> AVDD 2.9 V`，全部上升在 200 ms 内完成。
2. 所有电源稳定后，XCLR 保持低电平至少 500 ns。
3. XCLR 释放为高电平后，至少 1 us 再出现 INCK 上升沿。
4. XCLR 释放后至少 20 us 才开始寄存器通信。
5. 断电顺序为 `AVDD -> OVDD -> DVDD`；OVDD 下降前，INCK、SDA、SCL、XCLR、XVS、XHS 应为 0 V。

本实验驱动对目标模组采取以下可执行部分：

```text
probe resource acquisition
  -> RESET/PWDN asserted (logical 1, both DT GPIO_ACTIVE_LOW)
  -> optional DVDD -> DOVDD -> AVDD enable
  -> 1 ms conservative rail-settle delay
  -> PWDN deassert -> RESET/XCLR deassert
  -> wait >= 1 us
  -> set/enable 37.125 MHz MCLK
  -> wait >= 20 us
  -> read 0x311A

power-off / probe rollback
  -> assert RESET/PWDN
  -> disable MCLK
  -> optional AVDD -> DOVDD -> DVDD disable
```

由于目标模块使用本地无使能 LDO，驱动实际目标运行时后三路 `regulator_enable/disable` 不会执行；3.3 V 轨的上电必须早于驱动 probe，并由板级电源负责。若未来在另一块板上声明可控 regulator，必须同时声明三路，代码会拒绝部分描述；I2C 控制器的 SDA/SCL 低电平或高阻仍需由该板级 pinctrl/总线设计保证。

## 实验实现

### 文件和隔离关系

新增或修改的文件：

| 文件 | 用途 |
|---|---|
| `kernel/arch/arm64/boot/dts/rockchip/rk3588-alientek-2mipi1080x1920-2hdmi.dts` | 只在正确的 1080x1920 DTS 中 include 实验覆盖 |
| `kernel/arch/arm64/boot/dts/rockchip/rk3588-alientek-imx415-minimal.dtsi` | 禁用原厂 J20 `imx415@1a`、新增 `zzh,imx415-minimal` 节点、禁用 J20 下游实验分支 |
| `projects/rk3588_camera_bsp/driver/zzh_imx415_minimal.c` | 独立 I2C/clock/GPIO/regulator/时序/签名驱动 |
| `projects/rk3588_camera_bsp/driver/Kconfig` | 独立 `CONFIG_VIDEO_ZZH_IMX415_MINIMAL` tristate 选项 |
| `projects/rk3588_camera_bsp/driver/Makefile` | 外置内核模块 Kbuild 入口 |
| `projects/rk3588_camera_bsp/docs/阶段一硬件契约.md` | 本硬件证据和实现边界 |

原厂 `kernel/drivers/media/i2c/imx415.c`、原厂 Kconfig/Makefile、其余连接器定义均保留不改。实验节点没有 `port`、endpoint、module metadata、V4L2 graph 或 ISP/CIF 配置；同一实验 DTB 中不会让 `sony,imx415` 和最小驱动同时占用 J20 的 `i2c3` 地址 `0x1a`。

### 关键代码流程

- `zzh_imx415_read_reg()` 使用两个 `i2c_msg`，发送大端 16 位寄存器地址，再 repeated-start 读一个字节；传输不完整返回 `-EIO`，负 errno 原样保留。
- `zzh_imx415_write_reg()` 实现 16 位寄存器地址加 8 位数据的写操作；阶段一没有寄存器表，也不会调用写操作。
- probe 严格检查 raw I2C 能力、7 位地址 `0x1a`、MCLK、两个低有效 GPIO 和可选电源。可选电源只允许全有或全无。
- `zzh_imx415_power_on()` 在资源失败、时钟失败时按逆序回滚；probe 读签名后立即 power-off，成功返回时传感器不保持通电。
- 读到 `0x311A != 0xE0` 返回 `-ENODEV`；日志使用“reference signature”，不打印“official chip ID matched”。
- remove 再次执行幂等的安全断电和资源释放。代码不包含 V4L2 subdev、controls、`s_stream()`、mode table、Media Controller、RKCIF 或 RKISP。

## 构建、部署和验证

### 编译和部署

只进行 kernel 分项构建，不改 U-Boot `bootcmd`，不清理或重置厂商仓库：

```bash
cd /rk3588_dev
./build.sh kernel

KERNEL_CROSS=/rk3588_dev/prebuilts/gcc/linux-x86/aarch64/gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu/bin/aarch64-none-linux-gnu-
make -C /rk3588_dev/kernel \
    M=/rk3588_dev/projects/rk3588_camera_bsp/driver \
    ARCH=arm64 \
    CROSS_COMPILE="$KERNEL_CROSS" \
    CONFIG_VIDEO_ZZH_IMX415_MINIMAL=m \
    modules

./projects/scripts/deploy_net_boot.sh \
    -d rk3588-alientek-2mipi1080x1920-2hdmi \
    -m
```

部署脚本的 `-m` 只同步 Buildroot 已有模块；脚本完成其 `rsync --delete` 后，再安装本实验外置模块，避免它被删除：

```bash
KREL=$(cat kernel/include/config/kernel.release)
sudo install -D -m 0644 \
    projects/rk3588_camera_bsp/driver/zzh_imx415_minimal.ko \
    nfs_rootfs/atk_dlrk3588/lib/modules/$KREL/extra/zzh_imx415_minimal.ko
sudo depmod -b nfs_rootfs/atk_dlrk3588 "$KREL"
```

这里的 `sudo` 只用于 NFS RootFS 的安装、`depmod` 和现有部署脚本的属主保持；SDK 和外置模块编译仍以 `vscode` 用户执行。

本地执行结果（2026-08-01）：

- `./build.sh kernel` 返回 0；Image、三套候选 DTB、`resource.img` 和 FIT 生成成功。SDK 自带的 `check-power-domain.sh` 对其他 DTS 打印了 `Not Found io-domains` 提示，但没有导致构建失败。
- 外置 `CONFIG_VIDEO_ZZH_IMX415_MINIMAL=m` 模块构建返回 0，`modinfo` 显示 vermagic `5.10.209 SMP mod_unload aarch64`，无 V4L2 依赖。
- `deploy_net_boot.sh -d rk3588-alientek-2mipi1080x1920-2hdmi -m` 返回 0；随后已将外置 `.ko` 安装到 NFS RootFS `lib/modules/5.10.209/extra/` 并执行 `depmod`。

### U-Boot 最小命令

确认模组接在 J20 后，在开发板 U-Boot 执行：

```text
printenv nfsbootfdt nfsimage nfsfdt ipaddr serverip kernel_addr_r fdt_addr_r
run nfsbootfdt
```

这会下载部署脚本生成的固定 1080x1920 `Image + rk3588-alientek-nfs.dtb`。不得用旧的 `run nfsboot` 验证本 DTS 修改，因为它只下载 Image 并继续使用 U-Boot 已选的 resource DTB。

### Linux 最小命令

```sh
cat /proc/cmdline
mount | grep ' / '
cat /etc/rootfs-source
ip addr show eth0
uname -r

modprobe zzh_imx415_minimal
dmesg | grep -Ei 'zzh_imx415_minimal|reference signature|0x311a'
readlink /sys/bus/i2c/devices/3-001a/driver
cat /sys/bus/i2c/devices/3-001a/name
tr -d '\0' </proc/device-tree/i2c@feab0000/imx415-minimal@1a/compatible
```

期望的识别日志应包含：

```text
probing adapter ..., 7-bit addr 0x1a (wire write/read 0x34/0x35)
using module-local 3.3V-to-AVDD/DOVDD/DVDD LDOs
reference register 0x311a = 0xe0
reference signature matched (vendor reference, not an official unique Chip ID)
```

重复卸载/加载验证错误路径和幂等断电：

```sh
i=1
while [ "$i" -le 20 ]; do
    modprobe -r zzh_imx415_minimal || exit 1
    modprobe zzh_imx415_minimal || exit 1
    i=$((i + 1))
done
dmesg | tail -300
```

也可以使用项目内的板端验收脚本。源码和 NFS RootFS 部署位置分别为：

```text
/rk3588_dev/projects/rk3588_camera_bsp/scripts/verify_imx415_stage1.sh
/usr/local/sbin/verify_imx415_stage1
```

开发板以 root 执行并保留完整输出：

```sh
/usr/local/sbin/verify_imx415_stage1 20 2>&1 | \
    tee /tmp/imx415-stage1-validation.log
sha256sum /tmp/imx415-stage1-validation.log
```

脚本不会运行 `i2cdetect`、不会清空 `dmesg`、不会写 Sensor 寄存器。它会检查
运行 DT 中实验 compatible 和原厂同地址节点的 disabled 状态，再进行 20 次
module unload/load；每一轮必须重新绑定到 `3-001a`，且内核日志必须新增一次
“vendor reference”签名匹配。脚本末尾的 `PASS_CANDIDATE` 只表示这些运行检查
满足，不替代连接器照片、完整串口启动日志以及必要的 MCLK/GPIO 波形审核。

## 当前验收状态、遗留问题和回退

当前状态：**实验 DTS、独立驱动和 Kbuild 文件已创建并部署；2026-08-02
真实板端 20/20 次 remove/probe 均读取 `0x311A = 0xE0`，P1.1 软件与
I2C 功能门禁通过。** 该值仍只能称为厂商参考签名，不是 Sony 官方
唯一 Chip ID。本次未完成连接器照片、完整串口启动捕获及示波器波形验收，
因此不把软件时序实现过度表述为“已实测严格电源时序”。

遗留问题：

- 本次 `i2c3` 真实应答与 J20 契约一致，但仍需用连接器、丝印和排线照片补齐物理配置证据。
- `0x311A = 0xE0` 不是 Sony 公布的唯一 Chip ID，不能单凭该值证明芯片型号；它只能证明 I2C 通路和参考复位签名符合预期。
- 模组本地 LDO 无软件 enable，驱动无法验证真实三路电源的上升/下降波形；必要时需示波器测量 VCC3.3、AVDD、DOVDD、DVDD、MCLK、RST、PDN。
- 20 次 reprobe 稳定性和 I2C 应答已通过软件日志确认；J20 RESET/PWDN 物理电平、MCLK 和电源波形仍需仪器测量。

原厂回退方法：

1. 将模组移回原厂支持的连接器/保持原厂线缆。
2. 使用不包含 `rk3588-alientek-imx415-minimal.dtsi` 的原厂 1080x1920 DTS 重新执行 `./build.sh kernel` 和部署，或直接启动保留原厂 `sony,imx415` 节点的 eMMC 固件。
3. 不删除 `kernel/drivers/media/i2c/imx415.c`；网络启动验证回退时使用原厂 DTB 和原厂应用链路。

本实验没有修改 U-Boot 默认启动链、`bootcmd` 或原厂 IMX415 驱动。
