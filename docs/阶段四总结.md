# 阶段四总结：MLX90640 电气接入与原始 Subpage 读取

> 验收日期：2026-08-23（Asia/Shanghai，采用开发宿主机时间）  
> 平台：ATK-DLRK3588，Rockchip Linux 5.10.209  
> 结论：**P1.4 板端功能门禁通过；仪器波形不纳入当前验收，精确FOV型号在项目二标定前确认**

## 1. 验收范围

本阶段完成微雪 MLX90640 Thermal Camera 的实物接线、I2C5 定点识别、EEPROM
分段读取、400 kHz 总线配置、原始 pixel/aux RAM 读取以及 Chess 模式 Subpage
0/1 交替验证。本阶段输出的是原始测量数据，不包含温度计算，也不包含 P1.5
的 V4L2 Meta/VB2 ABI。

开发板 RTC 未校时，板端原始日志中的日期为 1970-01-01；验收日期以开发宿主机
和构建会话 `output/sessions/2026-08-23_19-13-28/` 为准。

## 2. 最终接线契约

| MLX90640 模组 P1 | 信号 | 开发板连接 |
|---:|---|---|
| 1 | SCL | JP5 pin 2，`I2C5_SCL_M0` |
| 2 | SDA | JP5 pin 4，`I2C5_SDA_M0` |
| 3 | GND | JP1（VOUT1）的 GND |
| 4 | VCC | JP1（VOUT1）的 3.3V |

必须保留以下边界：

- JP5 pin 10 是 `GPIO0_C6`，当前 DTS 用作 PCF8563 RTC 中断，不是电源；
- JP2（VOUT2）是 5V，不能给 MLX90640 供电；
- JP5 pin 2/4 右侧的 3.3V 表示 I/O 电压域，不表示信号脚可以供电；
- VCC/GND 是常供电物理接线，当前工具和 DTS 不控制 regulator 或电源 GPIO。

模组背面丝印、JP5 信号接线和 JP1 供电接线照片保存在
`evidence/stage4/2026-08-23/`。当前不具备万用表、示波器或逻辑分析仪，因此电压和400 kHz波形不纳入P1.4
验收；现有功能日志作为当前电气可用性证据。尚未确认的BAA/BAB/FOV只影响后续
跨光谱标定，项目二开始标定前再确认。

## 3. 实现与构建

### 3.1 只读 EEPROM 工具

`tools/mlx90640_readonly_probe.c`：

- 只访问默认 7 位地址 `0x33`；
- 读取 `0x8000/0x800d`；
- 每次按 32 word 分段读取 832-word EEPROM；
- 连续读取两份并比较，不写 MLX90640 寄存器。

### 3.2 原始 Subpage 工具

`tools/mlx90640_raw_probe.c`：

- 等待 status `0x8000` 的 data-ready bit；
- 按官方参考流程写 `0x0030` 清除 ready；
- 分段读取 `0x0400` 的 768 pixel word 和 `0x0700` 的 64 auxiliary word；
- 保存 status bit 0 的 Subpage ID和 `CLOCK_MONOTONIC` 时间戳；
- 支持保持当前配置，或临时设置 Chess + 8/16 Hz；
- 配置改变后丢弃两个流水线过渡 Subpage；
- 统计交替、周期、读取耗时、数据校验和哈希；
- 正常、失败或信号退出时恢复原控制寄存器。

两份工具均使用 AArch64 工具链以 `-O2 -Wall -Wextra -Werror` 交叉编译通过。
`mlx90640_raw_probe.c` 的 checkpatch 结果为 0 error；`volatile sig_atomic_t` 和
`PRIu64/PRIx64` 触发的 1 warning/2 check 属于用户态信号安全和标准格式宏，保留。

### 3.3 400 kHz DTB

目标 DTS 的 `&i2c5` 新增：

```dts
clock-frequency = <400000>;
```

`./build.sh kernel` 增量构建成功，部署脚本生成固定 1080x1920 NFS DTB。运行
设备树读取为 `00 06 1a 80`，即十进制 400000。

| 载荷 | SHA-256 |
|---|---|
| TFTP `Image` | `f76ad33c48520b79460425a204602936b986e706a7307ff99cd177d3d467eeb8` |
| TFTP `rk3588-alientek-nfs.dtb` | `f20be04d13111f0d81d4a4e5092bf0fc516998997e22c19c5eeee70335c4d20f` |
| EEPROM 1664-byte 大端文件 | `cc4628409b57ca3137065b10fd40c684fcef9d16ab493ace882710ad490185b2` |

## 4. 真机结果

### 4.1 100 kHz 基线

| 检查 | 结果 |
|---|---|
| 地址 | `0x33` 正常应答 |
| status/control | `0x0009 / 0x1901` |
| ID words | `0x131a-0x4948-0x0190` |
| EEPROM | 20/20 成功，双读均 `EEPROM_MATCH=1` |
| 单份 EEPROM 时间 | 约 204~206 ms |
| 原始 Subpage | 6帧，`0/1`严格交替，3对，0校验错误 |
| 原始读取时间 | 约 206~217 ms |
| Subpage 周期 | 约 508~513 ms（当前2Hz） |

### 4.2 400 kHz EEPROM

- 20/20 次完整读取成功；
- 每次内部双读均完全一致；
- 20次导出文件只有一个 SHA-256；
- 单份 EEPROM 时间约49~52ms，较100kHz约提升4倍。

### 4.3 8/16 Hz Chess Subpage

正式帧均在丢弃两个配置切换过渡 Subpage 后开始统计。

| 设置 | 正式Subpage | 完整pair | 周期范围 | 读取范围 | 交替错误 | 周期错误 | 数据错误 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 8 Hz | 20 | 10 | 126.52~128.94 ms | 47.80~57.45 ms | 0 | 0 | 0 |
| 16 Hz | 20 | 10 | 62.35~65.19 ms | 49.20~56.03 ms | 0 | 0 | 0 |

两次测试结束后均输出 `RESTORED_CONTROL=0x1901`，额外定点回读也为
`0x19 0x01`。这证明临时刷新率/模式变更没有残留到后续会话。

## 5. 共享总线回归

- I2C5 的 `5-0014` Goodix 触摸正常读取 ID 911并注册输入设备；
- `5-0022` FUSB302 保持驱动绑定；
- `5-0051` PCF8563 节点仍存在，但该重复节点在启动时探测失败，物理 RTC
  在 I2C6；没有证据表明这是400kHz修改新增的问题；
- 正式采集期间没有新增 I2C、timeout 或 NACK 内核日志。

## 6. 结论与下一阶段

P1.4 的软件/功能主门禁已经通过：实物可稳定应答，EEPROM缓存来源稳定，
400kHz 分段传输和8/16Hz Chess Subpage均有真实板端证据，可以进入 P1.5
设计版本化 V4L2 Meta/VB2 ABI。

以下内容不属于本阶段完成项：

- EEPROM校准参数解析和摄氏温度矩阵；
- BAA/BAB/FOV确认和跨光谱标定；
- V4L2 Meta、MMAP、poll、sequence、STREAMOFF Buffer回收；
- 逻辑分析仪对400kHz、repeated-start和上升时间的波形验收（当前无仪器，不纳入P1.4）；
- 双路并采、长稳和故障注入。
