# 阶段二总结：IMX415 独立固定模式 Sensor 驱动

> 验收日期：2026-08-08（Asia/Shanghai）  
> 平台：ATK-DLRK3588，Rockchip Linux 5.10.209，实物屏 1080x1920 版本  
> 结论：**阶段二目标路径板端验收通过**

## 1. 验收范围

本阶段验收的是独立 `zzh,imx415` Sensor 驱动从 I2C client、V4L2 Subdev、
Controls、runtime PM 到现有 RKCIF 短流的固定模式路径。阶段三的 RKCIF/RKISP
正式 RAW/NV12 画质、Host 错误恢复和长期可靠性不在本阶段结论内。

## 2. 实现与载荷

- 权威驱动：`projects/rk3588_camera_bsp/driver/zzh_imx415.c`。
- 内建入口：`kernel/drivers/media/i2c/zzh_imx415_builtin.c`，通过 include
  挂接同一份权威驱动实现；配置为 `CONFIG_VIDEO_ZZH_IMX415=y`。
- 设备树：固定部署
  `rk3588-alientek-2mipi1080x1920-2hdmi.dtb` 生成的
  `rk3588-alientek-nfs.dtb`，原厂 `sony,imx415` 同地址节点保持 disabled。
- 构建：`./build.sh kernel`、`./build.sh modules` 均成功；未刷写 eMMC、U-Boot
  或其他固件分区。
- 启动：板端执行 `run nfsbootfdt`，Linux 根文件系统来自 NFS。

## 5. 短流稳定性

- `/usr/local/sbin/verify_imx415_stage2 10`：10/10 轮 `PASS`，退出码 0。
- `/usr/local/sbin/verify_imx415_stage2 100`：100/100 轮 `PASS`，退出码 0。
- 每轮跳过 8 帧稳定期、采集 12 帧；每帧 `10506240` bytes，实测约 30 fps。
- `VIDIOC_STREAMON returned 0 (Success)`；无 `Cannot allocate memory`、RKCIF
  dummy buffer 分配失败、CSI timeout、overflow、IOMMU fault、Oops、BUG 或
  kernel panic。
- 测试结束时目标 I2C 设备 runtime PM 状态为 `suspended`。

验证脚本仍输出 `STAGE2_RUNTIME_CHECK=PASS_CANDIDATE`，这是脚本保留的固定
措辞；本总结的“通过”依据是脚本退出码、10/100 轮逐轮结果、Subdev/graph/
Controls 证据和阶段二目标路径日志的联合复核。

## 6. 结论边界与下一步

阶段二的独立固定模式 Sensor/Subdev/Controls/runtime PM 和现有 RKCIF 短流
链路已经通过，可以关闭 P1.2 并进入 P1.3。以下内容没有在本总结中冒充已完成：

- mode 表逐寄存器 readback、示波器/逻辑分析仪电源和 GPIO 波形；
- RAW Bayer 图样/画质以及 300/3000 帧正式 RAW 验收；
- RKISP NV12、Host 错误恢复、长时间运行和原厂 446 MHz 路径 A/B。

其他 I2C 总线未接摄像头节点的预期 probe 失败，以及无摄像头 RKCIF 实例的
`remote terminal sensor failed` 日志，不属于 `3-001a -> rkcif-mipi-lvds2`
阶段二目标链路。
